# V0.5.1 录后候选整理与代码检查

## 数据链路与本次范围

实时：麦克风 → LocalAudio / capture-worklet（4096点窗口、约20ms步进、能量起音）→ Pitchy 单音基频 → GuzhengApp 的 onFrame → PracticeEngine 的有界跟谱与评分。精调另经 FineTuningInput / TuningGate；节拍器按音频时钟调度，简谱光标按同一时间轴逐帧绘制。曲库和导入谱提供目标时间表。实时起音时只消费当帧单音音高，余音混合仍可能导致误判；本次没有足够原音证据安全修改此链路。

录后：ReviewTrial 本机解码重采样 → 一次性 Worker → Basic Pitch 帧/起音矩阵 → 官方 outputToNotesPoly → 原始 notes → 独立候选整理 → 回听与 JSON。它没有接入 PracticeEngine，不生成分数。调音、跟练、节拍器、简谱和评分代码未改。

## 整理方法

不改动官方原始 notes，不吸附曲谱，不按调式删音，不设置事件 amplitude 的绝对淘汰阈值。新增 review 包含版本、参数、每个原始索引、关联候选索引、原因和起音证据。

- 同刻（45ms内）或较低音仍持续时，较弱的整数倍频关系候选标为疑似泛音。
- 同音候选在前音结束后120ms内接续且响应降至前音的75%以下，标为疑似余音重检，事件不合并。
- 某音高的模型起音响应至少0.5且帧激活较此前基线增加至少0.12时，优先保留，保护轻弹同音和八度新起音。这里的0.5是起音矩阵响应，与事件平均 amplitude 不同；上述全部参数均为可审计的试验启发式，并非真琴校准结果。
- 独立弱音、非泛音关系的同时音、无关联证据的候选保留。强泛音、带新起音的泛音可能继续多检；轻弹八度或重复音也可能被误标，因此只做可展开的疑似分类，绝不扣分。

默认显示未标疑似的候选，并明确显示疑似数量；勾选“展开全部原始候选”可逐个回听。导出始终包含全部原始事件及整理原因。原始候选数、整理候选数都不能直接解释为实际拨弦数。

## 验证与限制

69项单元测试、TypeScript、Lint、GitHub Pages静态构建通过。新增合成事件覆盖轻音、强泛音、连续同音、八度真音、新起音保护、非调式音及输入不变性。

实际模型合成基准（默认0.5/0.3配置；16个目标音）：

|输入|原始候选|整理后候选|整理前后匹配目标|
|---|---:|---:|---:|
|短余音|19|16|16 / 16|
|长余音|68|57|16 / 16|

长余音仍有41个额外候选，不能用于可靠评分。复现 `node scripts/benchmark-basic-pitch.mjs`，直接使用项目固定依赖。目标时间只用于基准匹配，不传入整理函数。

桌面 Edge 390×844 浏览器运行实际模型，合成3音仍产生5个候选（2个泛音保留，起音保护优先），验证全部原始事件导出、展开、回听、取消、坏文件、直接录制和关闭资源释放，以及无上传请求。此结果不是iPhone实机或古筝准确率验收。

真实用户JSON仅在已忽略的work目录本地分析，不进入本文、公开测试或仓库。只有事件JSON，无法重跑音频模型、核对实际起音、音分或环境噪声。需要更多带原音的轻重拨弦/真八度样本才能继续收紧分类。
