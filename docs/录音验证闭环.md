# V0.6.0 录音验证闭环

## 使用顺序

1. 首页或练习结果打开“试用新识别 · 录音复核”，直接录一段、选择手机录音，或带入本次练习录音。
2. 停止录音后，原始文件自动保存在当前浏览器 IndexedDB。检查“已保存到本机样本库”的提示。无需先完成识别即可点击“下载原始录音”。
3. 点击“开始新引擎识别”，回听各候选；在“实际弹奏的音符序列”中填写如 `D4 D4 F#4 A4 D5 A4`，点击“保存纠正答案”。
4. 页面分别比较原始候选、整理候选与实际序列。只有音符顺序对照，不评节奏、音分或演奏好坏。重复音可能存在多种最小编辑对齐，不能把每个计数当作确定的物理起音结论。
5. 点击“下载完整备份（含录音）”保存一个 JSON，包含原音的base64内容、手写答案、全部历次识别、版本及规则参数。可主动发送这个备份进行分析；应用不会自动上传。
6. 下次打开“已保存样本”，选择一段重测，或点击“依次复测所有已纠正样本”。批量过程逐段使用原音运行模型，每次结果追加保存，可取消；失败时停止，不自动调参或发布。历史记录按当前填写的答案显示对照。
7. “恢复完整备份”能恢复录音、答案和历史记录。导入总是新建样本，不覆盖已有样本；无效备份会提示错误。未完成格式的答案草稿也能随备份保存、恢复，但不能加入整组对照。

## 原始录音保存边界

保存和下载均使用原始Blob，保留实际MIME类型和原字节，不把识别用的22050Hz单声道数据冒充原录音。直接录制的格式由设备MediaRecorder决定；停止时等待最终数据再保存。采音最长25秒，识别限制30秒/20MB。

正常停止后的录音会持久保存，刷新后可重新打开。录制中关闭对话框会被阻止，刷新会尝试触发浏览器离开提示。强制关应用、系统杀进程或设备断电时，尚未结束的录音不能保证保存。浏览器清理网站数据、隐私模式或存储回收也可能删除本机样本，因此提供独立下载及可恢复备份；不能承诺浏览器永久保管文件。

存储失败不会标为成功，当前页面仍可下载原音和完整备份。备份中包含原音，属于私人文件，不自动上传、不进入公共仓库。

## 工程实现

- `lib/review-samples.ts`：IndexedDB事务存储、原音文件名与下载。
- `app/ReviewNotebook.tsx`：样本库、手写答案、结果对照、历史、备份与恢复。
- `lib/review-comparison.mjs`：音名解析、最小序列编辑计数、备份结果校验。
- `app/ReviewTrial.tsx`：识别结果追加保存、独立重测/整组顺序重测、取消、录制关闭保护。

人工答案只用于比较，从不传入模型Worker。模型、候选整理算法、实时调音和实时评分未改，本版本提升验证效率，不宣称提高识别准确率。

## 验证

72项单元测试通过；类型检查、Lint、GitHub Pages生产构建通过。内存紧张时本机构建使用 NODE_OPTIONS=--max-old-space-size=384，没有修改依赖或关闭用户程序。

浏览器为桌面Edge的390×844手机视口，使用合成音：实际模型推理、刷新恢复、原音逐字节下载、纠正答案保存、备份音频逐字节一致、导入新增样本、两样本串行重测与历史保留、取消、坏录音、MediaRecorder直接录制与原音下载、存储失败下载退路、关闭资源释放均检查。原实时未校音练习与录音入口回归通过。未做真实iPhone/Safari文件保存实机验收。
