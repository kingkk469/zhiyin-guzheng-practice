# V0.7.0 新起音判音接入

## 继承与核验

临时实验代码已完整复制到已忽略的work目录，11个文件逐一核对SHA256一致，未删除原目录。检查时主仓库HEAD仍是V0.6.0，没有对方已落地的应用修改。

复跑原实验：39组两弦叠音旧MPM通过22组、残差通过39组；整曲183个可评分音的旧/flux方案正确判定比例为90%/99%、58%/99%、13%/97%。这些是原实验数据复现，不能直接当成新版手机或真琴准确率。

## 已实施

测音准模式：AudioWorklet保留原精调帧与RMS起音，同时传递连续PCM小块；独立Worker采用有界缓存的流式谱通量起音检测，再用起音前后频谱差和基音/泛音模板判别新拨弦。起音前保护12ms，起音后跳过15ms，判音窗口4096点；44.1/48kHz流式用例包含每段20ms投递延迟，检测回传在150ms以内。此为合成和桌面测试，不保证iPhone上的实际总延迟。

判音候选只取D调21根空弦，±50音分粗扫后细化，不读取当前曲谱。新增声音不足、候选分离度不足、接近搜索边界、起音过密、过载或缺背景时返回未判断。0.9/0.4是门控标记，不是统计正确概率。当前未实现可靠和弦检测，撮、摇指、快速连音以及非D调空弦不在支持范围。

录后：保留Basic Pitch原始候选及旧整理结果，新增独立“新起音判音”事件、理由、参数，使用相同残差判音核心。由于录后输入为22050Hz，窗口采用2048点/8192 FFT。录音开头、结尾不足完整窗口时保留未判断事件；不把负切片当作录音末尾。人工答案旁增加新方法对照，原音、所有方法结果随样本历史和完整备份保存。

校音与巡检仍走原Pitchy/RMS逻辑；跟练、节拍器和评分容差未放宽。规则版本变为0.7.0-residual-trial以区别新旧成绩。实际采音中断、Worker失败、任务积压或回传落后350ms会暂停，不退回旧算法继续打分。结束、暂停与关闭释放识别Worker。

## 验证

77项测试、类型检查、Lint和Pages静态构建通过。包含39组叠音、静音、重复音、八度跳、录音尾部截断、44.1/48kHz流式起音时间与有界缓存。一个44.1kHz长余音轻重复用例返回未判断，未把它伪装成识别正确。

实际Edge浏览器合成实时练习通过（音符/节奏100，原音可回听并带入复核）；录后实际模型推理验证Basic Pitch三个目标产生五个候选，新起音产生三个对应音。备份、原字节下载、恢复、整组重测和取消检查通过，无音频上传。

新增 scripts/benchmark-residual-stream.mjs 使用实际流式模块和评分器运行整组曲谱，不通过已知起音直接调用判音器；注入10%错弦、15ms时差、低频衰减和余音。结果写入已忽略的outputs目录。其结果仍只代表合成输入。

尚需用户真琴验证，特别是义甲触弦、轻重变化、噪声、房间回响和Safari长时间运行。新算法不是“有一次起音就必然有一个正确音”，仍可能漏起音或误触发，必须结合原音核对。
