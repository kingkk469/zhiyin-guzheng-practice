# 古筝陪练：成熟识别方案调查与接入试验

调查日期：2026-09-24。目标是连续拨弦时的音符、起音和跟谱，不是仅测单根弦的调音器。

## 结论与当前接入状态

有可复用的开源组件，也有商业演奏评测产品。但本轮未找到已证实满足“古筝、iPhone网页、本机处理、低误报、250毫秒内反馈”的即插即用完整方案。

已下载并实际运行 Spotify Basic Pitch 1.0.1，接入本地独立测试脚本，保留模型与依赖的许可证。结果显示，未经适配直接替换线上引擎仍会多检，故线上继续保持V0.4.3，没有把试验模型当作可靠评分发布。未上传用户报告、图片或录音，未注册付费服务，未联系厂商。

若目标是尽快采用完整产品，商业候选优先验证 MatchMySound。若要求免费开源、本机运行，需要多音识别、跟谱与评分分开适配验证，不能承诺安装一个包就准确。

## 实际运行 Basic Pitch 的结果

版本：`@spotify/basic-pitch@1.0.1`，TensorFlow.js 3.21.0；官方包自带模型。权重742,392字节，SHA256：`B142A95737A52E1E412D5F92E73D8BB80DFE8D04941ACC0702F11F4524FB377C`。

脚本：`scripts/benchmark-basic-pitch.mjs`。结果：`outputs/basic-pitch-benchmark.json`。

输入为《日常节奏小练习2》第2—5小节16个音的合成拨弦信号，70拍，22,050Hz单声道，共约7.86秒。使用基音加0.3倍二次谐波、指数衰减；这不是古筝录音。目标谱只用于生成输入和测量，不传给模型，不以目标音删掉多检事件。音高一致且起音误差在100毫秒内视为匹配，每个检测事件只能匹配一次。

|输入|官方配置|输出音符事件|匹配16个目标音|额外/不匹配事件|桌面CPU推理时间|
|---|---|---:|---:|---:|---:|
|短余音，振幅半衰期约87ms|README示例0.25/0.25|24|16|8|约8.0秒|
|短余音|函数默认0.5/0.3|19|16|3|同一次推理结果|
|长余音，振幅半衰期约693ms|README示例0.25/0.25|93|16|77|约9.3秒|
|长余音|函数默认0.5/0.3|68|16|52|同一次推理结果|

含义：模型具备保留叠加目标音的潜力，但当前无适配的直接输出多检明显，不能用“16个都找到了”当作评分可用的证明。结果只针对这些合成样本，不是古筝精确率，也不能证明旧引擎整体优于新模型。CPU耗时不是WebGL性能、不是iPhone测量值。

另一个限制是[官方JS源码](https://github.com/spotify/basic-pitch-ts/blob/main/src/inference.ts)的输入窗口为`22050×2−256`个采样，约1.988秒，并带重叠与整段音符后处理。不能直接承诺250毫秒内输出可靠音符事件。上游还存在[公开iPhone问题报告](https://github.com/spotify/basic-pitch-ts/issues/22)；这是一条待核验的兼容性线索，不代表所有iPhone版本都失败。

本地复现（项目目录内）：

```powershell
npm install --prefix work/basic-pitch-lab --ignore-scripts --no-audit --no-fund --save-exact @spotify/basic-pitch@1.0.1 @tensorflow/tfjs@3.21.0
node scripts/benchmark-basic-pitch.mjs
```

## 接入决策

1. 不用缺乏古筝验证的模型直接替换线上评分。现有跟练、节拍器、单弦调音可继续使用；连续演奏评分仍属于试验功能。
2. 开源路线：Basic Pitch已接到本地试验，下一步用真实标准演奏、故意错音、连续同音与余音样本比较；先验证弹后复核，再考虑实时切块和手机推理。时钟仍以设定速度为准，跟谱器不能迁就演奏速度从而消除节奏错误。
3. 商业路线：向MatchMySound申请古筝专项试用，确认是音频参考对比还是逐音事件输出、能否接入自有简谱、iPhone支持、起音时间/音高API、是否上传录音、数据保留、授权费与实时延迟。仅“支持所有有音高乐器”的泛化表述不足以采购。
4. 若商业技术只能弹后反馈，须明确这是产品范围变化，不能当成完成原来的实时陪练需求。

继续比较的关键缺口是原始录音：之前的JSON只保存旧检测器的判断与部分音高，无法恢复已经丢失的声学信息。需要用户提供的原始录音做本地分析；任何云端供应商试用上传另行获得授权。

## V0.5.1 后续验证

已接入可逆的候选整理：疑似泛音/余音单独标记，保留全部原始事件与模型起音证据。默认配置合成短余音19→16候选、长余音68→57候选，均保留16个目标；长余音仍有41个额外候选，不能作为评分可用的证明。三音浏览器合成样本仍为5个候选，新起音保护也会保留部分泛音。规则、参数、完整边界见[录后候选整理说明](../docs/录后候选整理说明.md)。
